title: Skill catalog
description: The 26 skills shipping across the three agent tiers, grouped by the tier that holds them.
---

Every skill is a `SKILL.md` bundle under `agents/<tier>/skills/`. Skills are **allocated to the tier whose authority they match** — an agent only ever sees its own set, and a skill that acts outside its tier's scope would be refused by that tier's broker before anything is touched. An agent loads a skill on demand from the `description:` field in its frontmatter; clicking through to source below gives you the full procedure the agent follows.

For how skills are structured and invoked, see [Concepts → Skills](/kube-agents/concepts/skills/).

26 distinct skills ship: **12** on platform, **13** on cluster-admin, **12** on developer-team.

## Shared by all three tiers

| Skill                                                                                                                      | Description                                                                                                                                                                                       |
| -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`apply-change`](https://github.com/gke-labs/kube-agents/blob/main/agents/platform/skills/apply-change/SKILL.md)           | Change the cluster or cloud. Build an Action Envelope and submit it to your broker, which classifies it, plans an undo, journals it, executes it and verifies it. The only way to write anything. |
| [`detect-drift`](https://github.com/gke-labs/kube-agents/blob/main/agents/platform/skills/detect-drift/SKILL.md)           | Watch the tier's own scope for drift and fix what you find through the broker. Detection is read-only; remediation is an Action Envelope, never a pull request.                                   |
| [`gke-observability`](https://github.com/gke-labs/kube-agents/blob/main/agents/platform/skills/gke-observability/SKILL.md) | Workflows for setting up and auditing observability (logging, monitoring, tracing) on GKE — fleet view, cluster view, or workload view depending on the tier.                                     |
| [`read-knowledge`](https://github.com/gke-labs/kube-agents/blob/main/agents/platform/skills/read-knowledge/SKILL.md)       | Retrieve Operational Knowledge Framework (OKF) entries — runbooks, blueprints, observations — via a strictly read-only sparse checkout. A knowledge layer, not a channel to another agent.        |

## Adding a new skill

See [Concepts → Skills](/kube-agents/concepts/skills/#adding-a-new-skill) for the process. New skills land under `agents/<tier>/skills/<name>/SKILL.md`, under the tier whose authority the skill needs; if they should also run on schedule, add an entry to that tier's `cron/jobs.json`.
