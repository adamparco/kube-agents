# --- builds compile whole packages (LSN-037) -------------------------------------------------
# `go build cmd/broker/main.go` compiles one file and pretends the rest of the package is absent.
# It is indistinguishable from the correct spelling until a package gains its second file, and then
# it fails on the symbols in the file it dropped. Dockerfile.broker broke exactly that way when
# `waitforbroker.go` landed: `go build ./...`, `go vet ./...` and `go test ./...` were all green and
# six of seven CI checks passed, because the image build was the only build in the repo not
# compiling packages. Late, far from the edit, and it reads as an infrastructure fault. Build inputs
# are globbed rather than listed, so a new Dockerfile is covered unedited (LSN-036), and finding no
# `go build` at all is a FAIL, not a vacuous pass (LSN-035). `--negative-control` is the `¬`.
python3 dev/tests/go-build-targets-packages.py
python3 dev/tests/go-build-targets-packages.py --negative-control
