# The L2 regression chain — checks that need a real cluster, and cannot run in PR CI.
#
# Companion to L0-CHAIN.txt. Split because the two have genuinely different triggers, not because
# L2 matters less: the load-bearing security negatives (egress actually denied, admission actually
# rejecting, isolation actually isolating) all live here. L0 proves a manifest is well-formed; L2 is
# the only thing that proves it is enforced. That distinction is LSN-006, and it is why a lesson may
# legitimately be closed by a script in this file even though no pull request runs it.
#
# Each line takes a --context argument. Every one of these is a DESTRUCTIVE test target: they apply
# deliberately-bad RBAC, delete pods, and exercise denial paths. The guard in each script is an
# anchored `case` on gke-scratch-* and invariants-gate.py asserts it stays anchored — a substring
# match is LSN-005, and the live GKE cluster is one `*` away. That the accepted set is now a single
# anchor and not two is a STRENGTHENING: the guards accept strictly fewer contexts than they did.
#
# Every line CARRIES its own context, still, even though every line now carries the SAME one.
#
# The single target is the end of a two-step consolidation. There used to be two clusters, because
# precondition P4 meant neither could serve the whole file: one hosted the operator on a dataplane
# that accepted NetworkPolicy and enforced none of it, the other enforced but hosted no operator.
# They differed in two create-time knobs, dataplane and node count, which are orthogonal — so up.sh
# built their union and there was one. On 2026-07-26 that union moved off the laptop to a remote GKE
# cluster (dev/cluster/up.sh — Dataplane V2, 2 nodes, Workload Identity), which changes where it runs
# and not what it is. Running several control planes on one laptop VM is also what LSN-026 cost us:
# three FALSE security failures from memory pressure alone, on a substrate no longer in the loop.
#
# The per-line context is NOT collapsed back into the run loop now that the values agree. It was a
# run-loop default once. That was a single-definition-site violation dressed as a convenience: the
# paragraph here explained that the targets differ and then handed the reader one loop that gave
# every line the same one. Followed literally on 2026-07-25 it sent `closed-allowlist-l2.sh` and
# `multi-agent-namespace-l2.sh` at the operator-less cluster, where both correctly returned
# P1-UNVERIFIABLE (rc 3) — two of six lines silently not run, and only visibly so because P1 refuses
# to guess. A default target is a guess about which cluster a check needs; the check knows, so the
# line says. That the guess would currently be RIGHT is exactly why re-introducing it would be hard
# to notice, and the next time the targets diverge is the run nobody would check.
#
# Run:  while read -r c; do case "$c" in ''|\#*) continue ;; esac; eval "$c"; done < dev/L2-CHAIN.txt
#
# Precondition P1 applies to every line that tests a DEPLOYED image, which is every line above the
# Phase 9 heading: `bash dev/cluster/reload-images.sh <what> <ctx>` builds, pushes, and deploys BY
# DIGEST, then P1 asserts the running imageID digest equals the build under test. A green here
# against a stale image is LSN-001, and no line of this file can detect that on its own — deploying
# by digest is what makes that trap unrepresentable rather than merely detected.
#
# The qualifier is new and it is a narrowing of scope, not of rigour. A CLIENT-SIDE probe — one that
# compiles the working tree and connects to the cluster as a client, rather than asserting against
# something running in a pod — has the working tree as its build under test by construction, which
# is the property P1 exists to establish. Demanding P1 there would mean deploying an image the check
# never looks at, and a precondition satisfied by an irrelevant act is worse than no precondition:
# it reads as coverage. Each such line says so in its own header and says what replaces P1. When the
# component a client-side probe stands in for becomes reachable in a pod, its successor check needs
# P1 in full, and the header names that successor.

# --- the standing regression suite ----------------------------------------------------------
# The standing line is the LAST CLOSED PHASE'S GATE, and nothing else. Phase 8 closed on 2026-07-27
# and this line still said verify-phase7.sh until 2026-07-30, which cost two things that are worth
# naming because neither is visible from the chain file.
#
# The first is coverage: verify-phase7.sh reaches phases 2-6, so for three phases the standing
# regression did not include the six Phase-8 suites at all. They were still run — they are listed
# individually below — but they were run as Phase 8's own evidence rather than as the floor every
# later phase has to clear, which is a different claim about the same commands.
#
# The second is subtler and is the reason this comment is this long. invariants-gate.py derives the
# set of scripts it lints for declared preconditions from the TRANSITIVE CLOSURE OF THIS FILE
# (_l2_scripts_in_scope). A phase gate that is in no chain line and that nothing else calls is
# therefore outside that closure: verify-phase8.sh, the single script that renders Phase 8's verdict,
# was never once asked which artifact it was judging. The lint was not broken and the script happens
# to declare its preconditions properly; the point is that nothing checked, for three phases, and the
# only way to find that out was to ask why the standing line was a phase behind.
#
# So: verify-phase8.sh is the whole prior build in one command. It runs verify-phase7.sh (=> phases
# 2-6, chaos C1-C4, 03 §11 negative attenuation, the goldens and `go test ./...`) and all six Phase-8
# suites. It is listed FIRST because a phase's new L2 evidence is worth nothing if it was gathered on
# a cluster where the previous phases had already broken.
bash dev/verify/verify-phase8.sh gke-scratch-kube-agents-dev

# V-REV-001 at L2 at POPULATION scale — "100% of executed non-gated ActionRecords carry a validated
# undo plan". broker-execute-l2.sh already scores V-REV-001 and its row is a real result; it is also
# a result at n=1, on one hand-written apply of one ConfigMap. 100% of one is a number that cannot
# distinguish a working undo planner from a planner that happens to know one verb.
#
# THIS RUNS THE WHOLE SOAK CORPUS. dev/verify/fixtures/soak_corpus.py --table is the population;
# dev/verify/fixtures/undo_coverage_probe.py submits one envelope per row from inside the cluster,
# on the agent's own reader identity, through the broker's real front door — a fresh nonce per
# envelope, because nonces are single-use. The corpus supplies shape and target; the payload is
# synthesised, so a row is a real create/apply/patch/scale/delete against a real seeded object and
# not a replay of a recorded body. Everything is dry-run: Phase 9's defining constraint (07 §2) is
# that the entire safety machinery is exercised with no write authority anywhere.
#
# WHAT "EXECUTED" MEANS HERE is the broker's own stamp, status.timestamps.executionStarted — the
# moment it issued the first mutating call — rather than a guessed-at set of phase strings. A record
# the classifier gated never gets one and is correctly outside the denominator; on the run recorded
# in verification/results.csv that is exactly the two `delete Deployment` rows, PendingApproval,
# class gated, strategy none, which is the classifier doing its job.
#
# FOUR WAYS A NON-GATED EXECUTED RECORD FAILS, each scored by name rather than as one lump: no undo
# plan at all (`no-undo-plan`), a plan whose strategy is `none` (`strategy-none-on-non-gated` —
# StrategyFor's own closing comment is "anything else ⇒ none ⇒ gated", so none on a record that was
# NOT gated is the two halves disagreeing), a plan that is present and unvalidated
# (`unvalidated-plan`), and a validated plan with zero steps (`stepless-plan`). An executed record
# carrying no risk class at all is `unclassified-executed-record` and fails too, rather than
# quietly leaving the denominator.
#
# ATTRIBUTION IS AN ARM, NOT AN ASSUMPTION. The tenant namespace is this suite's own and it is left
# standing between runs ([[LSN-045]]), so the journal accumulates: A-5 intersects every mined record
# against THIS run's actionId set and prints the count it left outside. Without it the denominator
# grows every run and a stale 100% reads like coverage improving.
#
# AND THE SHADOW MUST HOLD. A-6 re-reads all 37 seeded targets after the run and fails on any
# create, mutation or delete. A dry-run soak that quietly wrote would still score V-REV-001 green.
bash dev/verify/undo-coverage-l2.sh gke-scratch-kube-agents-dev
